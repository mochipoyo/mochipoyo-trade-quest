対象：2D 版（`index.html`）・3D 版（`3d/index.html`。5体のいるマップは 3D 化していないので 2D の表示）

### 戦いの流れ
1. シンボルに触れる（はじめての相手）／話しかける（決定ボタン）
2. 専用の画面：名前・★・分野、モンスターの自己紹介、「我が問いに答えてみよ！」
3. 間違えた場合の損失（所持金の何%・上限・いまの所持金で奪われる額）を、問題を見る前に表示。「今は挑まない」で何も起きずに離れられる
4. 「挑む」で問題と4択（チャートの問題はデータから描く。数値の表も見られる）
5. 選んでから「この答えで確定」（誤タップ対策）。時間制限なし
6. 判定 → 正解の選択肢と解説 → 「とどめを刺す！」／「次へ」
7. 正解：光の筋・白い閃光・粒になって消える演出。経験値・ゴールド・初回は称号と記念アイテム。二度と現れない
8. 不正解：「残念だったな！ お前のゴールドはいただいた！」。金貨が飛び、奪われた額を表示。モンスターは煙を残して逃げる（「ガーン……」）。HP・MP・仲間の状態は変わらない。経験値・報酬なし。ゲームオーバーにならない

### 1回だけ確定する仕組み（不具合対策）
- 問題を出した時点で「出している途中の問題」（問題ID・確定の番号・並びの種）をセーブに書いて保存する。いったん離れても、再読み込みしても、次は同じ問題・同じ並び（別の問題に引き直せない）
- 確定ボタンを押した瞬間に、選択肢と確定ボタンを無効にする。`Quiz.settle` は同じ確定の番号を2回受け付けない（2回目は前の結果を返すだけで、ゴールドも報酬も動かない）
- ゴールドの増減と記録は、同じセーブデータの中で同時に書き、すぐ保存する（保存は1つの JSON をまとめて書く）。保存の前に再読み込みすれば、どちらも反映されていない状態に戻る
- 討伐済みのモンスターには、何度確定を送っても報酬は出ない
- 通常の戦闘の状態（Combat・BattleUI）には触れない。3D 版でも同じ画面

### 奪う金額
`floor(min(所持金 × 損失率, 上限))`。所持金が1G以上で0Gになるときは1G。所持金0Gなら0G。マイナスにならない。減算は1回だけ。

- 近づくと「不思議な気配がする……」、近くでは頭の上に「？」の吹き出し

## 3. 画像（仮の画像）と素材の仕様

**いまの画像は、コードで描いた仮のドット絵です（`js/core/quizmonart.js`）。高品質なイラストとして完成したものではありません。**

- 5体とも 96×96 の論理ピクセルに描き、背景は透明、上下左右に4ピクセル以上の余白（`qart_bbox.js` で確認）。戦闘画面では2倍（192×192）以上、マップでは約54ピクセルの高さで表示
- 名前と能力を反映：モグラン（眼鏡・巻物・本の小型獣）、ミラグ（半透明の幻影が重なる狐型の魔獣・鏡の破片）、ガルゾ（金貨袋を背負う赤い鬼）、ゼルキス（波形模様と巨大な魔眼の球体）、アルカディア（翼と天秤と冠の獅子型の守護獣）
- 2D 版・3D 版のどちらでも同じ絵（どちらも 2D の Canvas で描く）

### 正式な画像に差し替えるとき
1. 透過 PNG を用意する：正方形（推奨 384×384 以上）、全身がキャンバスに収まり、上下左右に1割程度の余白、足元は下端の中央付近
2. `assets/quiz_monsters/quiz_monster_00N.png` などに置き、`js/data/asset-manifest.js` に登録する（アセットのテストは、`assets/` の下のファイルがすべてマニフェストに載っていることを確かめる）
3. `js/core/quizmonart.js` の `QUIZ_ART_FILES` に ID とパスを書く（例：`QUIZ_ART_FILES.quiz_monster_001 = 'assets/quiz_monsters/quiz_monster_001.png'`）。読み込めたら画像を使い、読み込めないときはコードの絵に戻る

各問題：固有ID（qz1_01〜qz5_20）・問題文・選択肢4個・正解1個（データでは元の番号0。画面でまぜる）・解説・難易度（★の数）・対象モンスター・カテゴリー（師匠の流派と対応）・必要に応じてチャートのデータ（ローソク足の四本値、EMA・RCI の値、確定した高値・安値、価格と MACD の山・谷）。

- 「次に上がるか下がるか」を正解のある問題として出さない。問うのは、定義・前提を書いたルールへの当てはめ・計算・示したデータの読み取りだけ
- 相場の予測が確率的であることを学べる問題（期待値・連敗の確率・ダイバージェンスやRCIは「可能性」）を含む。ルールの問題の解説の下に「条件を満たしても結果は保証されません」と出す
- 計算・データの問題は、答えを式（`check`）やデータ（`verify`）から出す関数を持つ

### 検証（`quiz_test.js`）
- 100問・各20問、ID・問題文・選択肢の重複なし、選択肢4個、カテゴリー・流派・難易度の対応
- 計算・データで答えを出す39問：答えが正解の文にだけ入っていて、誤りの選択肢には入っていない（数字の桁の境目まで見る）
- ローソク足の四本値が矛盾しない、線の長さがそろっている
- 選択肢を40通りまぜても、文と番号の対応がずれず、正解はちょうど1つ。正解の表示位置はほぼ均等
- 奪う金額（境目の値を含む41通り＋0〜30,000G の全範囲）、確定は1回だけ、正解でだけ討伐済み、報酬は1回、所持金0G・1G、保存して読み込んだあとの二重処理なし、古いセーブ・壊れたセーブの補完、出題の一巡、出している途中の問題
- 別の担当（自分の判断と切り離したレビュー）が100問の内容を読み、正解の誤りは0問。指摘7問（「許容損失に収まる最大の数量」の言い方、連敗の確率の問い方、MACD の一般的な設定の補足など）はすべて直した

## 5. 師匠・必殺技との連携
- 問題のカテゴリーは、師匠の流派（`js/data/ultimates.js`）と対応する。その流派で修行（チャート修行・試験）した主人公は「師匠の教え」（ヒント）を思い出せる。上級試験に合格した流派なら、誤りの選択肢を1つ消せる
- 修行していなくても答えられる（ヒントがないだけ。正解の可能性は同じ）
- クイズモンスター戦では、通常の攻撃・必殺技は使わない（クイズの正誤だけで決まる専用のルール）。必殺技50種類・チャート戦闘の処理は変えていない
- セーブの名前空間 `d.quizMon`：モンスターごとの討伐・討伐日時・挑戦回数・正解・不正解・奪われた累計・初回報酬・発見、出題履歴、問題ごとの回答数、称号、確定の記録、出している途中の問題。古いセーブは `State.migrate` → `Quiz.ensure` で初期値を補う（ほかの項目は変えない）
- 将来の「討伐図鑑」「トレード知識の習熟度」：`Quiz.mastery(d)`（分野ごとの回答数・正解数）と図鑑の画面をすでに用意
