# クラウドセーブ（PC・スマホでセーブを共有）の設定手順

クラウドセーブは **Supabase**（外部のサービス）を使います。ゲーム側の仕組み（ログイン・保存・競合の判定・オフライン時の扱い・画面）は実装済みですが、**接続先の Supabase のプロジェクトを作って設定するまで、クラウドセーブは「設定待ち」と表示されて使えません**。そのあいだも、ゲームは今までどおり端末のセーブで遊べます。

> 確認できていること：ゲーム側の動きは、手元の PostgreSQL（本物）に下の SQL をそのまま流した「Supabase のまね」に対して、PC とスマホ（エミュレーション）の2台で確認しました。
> **未確認：本物の Supabase につないだ動作**（プロジェクトがまだないため）。設定が済んだら、下の「確認のしかた」で確かめてください。

## 1. プロジェクトを作る
1. https://supabase.com でアカウントを作り、**New project** を作る（地域は日本から近い Tokyo などを選ぶと速い）。データベースのパスワードは保管しておく（ゲームには入れない）。
2. 料金：無料のプランがあります。公式の料金ページ（2026年11月に確認）では、無料のプロジェクトは**1週間使われないと一時停止**され、ダッシュボードから再開が必要です。続けて公開するなら有料プランも検討してください。最新の条件は https://supabase.com/pricing で確認してください。

## 2. 表と関数を作る（SQL を1回流す）
1. ダッシュボードの **SQL Editor** を開く。
2. このフォルダの [`supabase-setup.sql`](supabase-setup.sql) の中身をすべて貼り付けて **Run**。
   - セーブの表 `mtq_saves`、前の版の表 `mtq_save_history`（スロットごとに最新5件）、保存用の関数 `mtq_put_save` ができます。
   - **行単位のアクセス制限（RLS）**：ログインした本人の行しか読めません。表を直接書き換える権限は外してあり、保存は関数だけ（本人の行だけを、リビジョンを確かめて書く）。
   - 何度流しても壊れないように書いてあります。

## 3. ログインの設定（メールのログインリンク）
1. **Authentication → URL Configuration**
   - **Site URL**：`https://mochipoyo.github.io/mochipoyo-trade-quest/`
   - **Redirect URLs** に追加：`https://mochipoyo.github.io/mochipoyo-trade-quest/**`（2D版の `index.html` と 3D版の `/3d/` の両方に戻れるように）
2. **Authentication → Emails（Email Templates）** の「Magic link or OTP」（初めてのログインで別のメールが届く場合は「Confirm signup」も）に、6桁のコード `{{ .Token }}` を書き足してください。
   スマホのメールのアプリでリンクを押すと、アプリの中のブラウザで開いてしまい、ゲームを開いているブラウザでログインできないことがあります。そのときはゲームの「メールの6桁のコードを入力」から入れられます。
   例：
   ```html
   <h2>もちぽよトレードクエストにログイン</h2>
   <p><a href="{{ .ConfirmationURL }}">ここを押してログイン</a></p>
   <p>リンクが使えないときは、ゲームの「コードを入力」にこの6桁を入れてください：<b>{{ .Token }}</b></p>
   ```
3. **メールの送信元（SMTP）— プレイヤーに公開する前に必須**
   Supabase に最初から入っているメール送信は、公式の説明では **プロジェクトのメンバーのアドレスにしか送れず、1時間に2通まで**（変わることがある）で、本番には独自の SMTP を設定するよう案内されています。
   プレイヤーがログインできるようにするには、**Authentication → Emails → SMTP Settings** で、メール配信サービス（例：Resend・Brevo・SendGrid など）の SMTP を設定してください。送信元のドメインの認証など、配信サービス側の設定も必要です（サービスごとに手順が違うので、選んだサービスの案内で確認してください）。

## 4. ゲームに接続先を入れる
1. **Settings → API Keys**（または **Connect** の画面）で、次の2つを確認する。
   - プロジェクトの URL（`https://xxxxxxxx.supabase.co`）
   - **publishable キー**（`sb_publishable_` で始まる。公開してよいキー）
2. リポジトリの [`js/cloud-config.js`](../../js/cloud-config.js) を次のように書き換える（GitHub の画面で編集してコミットすれば公開されます。または値を教えていただければ、こちらで入れてテストしてから公開します）。
   ```js
   window.MTQ_CLOUD = window.MTQ_CLOUD || { url: 'https://xxxxxxxx.supabase.co', publishableKey: 'sb_publishable_xxxxxxxx' };
   ```
   - **秘密の鍵（`sb_secret_…` や `service_role`）は絶対に入れないでください**。公開リポジトリに入れると、誰でも全員のセーブを読み書きできてしまいます。
   - 旧来の anon キーも使えますが、Supabase は anon・service_role キーを2026年末までに廃止予定と案内しています。publishable キーを使ってください。

## 5. 確認のしかた（設定が済んだら）
1. PC で 2D版を開き、「データ管理 → クラウドセーブ → メールでログイン」。届いたメールのリンクを開く（またはコードを入力）。
2. セーブのあるスロットを選び「クラウドへ保存」。
3. スマホで同じメールアドレスでログインし、そのスロットを「クラウドから読み込む」。PC の続きから遊べることを確認。
4. スマホで少し進めて保存 → PC の「クラウドセーブ」で「クラウドの方が新しい」と出て、読み込めることを確認。
5. ダッシュボードの **Table Editor → mtq_saves** に行ができていることを確認（ほかの人の行は、その人にしか読めません）。

## ゲームの中での動き（まとめ）
| 場面 | 動き |
|---|---|
| ログイン | メールのログインリンク（メールの6桁のコードでも可）。ログインの情報はブラウザに保存（2D版・3D版で共通）。期限が切れたら自動で更新 |
| 保存 | 端末に保存したあと、「自動同期」がオンのスロットはクラウドへも送る（オートセーブは少し待ってから） |
| 自動同期 | スロットごと。最初に「クラウドへ保存」か「クラウドから読み込む」をしたスロットがオンになる |
| オフライン | 端末には保存でき、遊び続けられる。クラウドへは「未送信」として覚え、オンラインに戻ったら送る |
| 競合 | ほかの端末が先にクラウドを更新していたら（サーバーのリビジョン番号で判定）、保存せずに「競合」。保存日時・レベル・場所・プレイ時間などを並べて、どちらを使うか選ぶ |
| 消えないように | 端末のスロットを置き換える前は、端末内にバックアップ（最大5回分）。クラウドは上書きの前の版を履歴に（スロットごとに5件） |
| 2D版と3D版 | 端末のセーブ枠は別のまま（勝手にまとめない）。クラウドの同じ番号のスロットを、どちらの版からも読み書きできる。端末ごとの設定（音量・操作パッド・歩く速さなど）と3D版のカメラの設定は共有しない |
