# もちぽよFXクエスト 3D移行設計書（Phase 0）

対象：v5.6（`feature/3d-remaster` ブランチ）　作成：Phase 0 / Phase 1 実装時点

この文書は「既存の2D版を壊さずに、段階的に本格3D RPGへ移行する」ための設計です。
Phase 1（ポヨ村の3D化）は、この設計どおりに実装済みです。実装の確認結果は `docs/3d/05_phase1-test-results.md` を参照してください。

## 1. 現在のリポジトリ解析（2D版 v5.6）

### 1-1. 構成（確認済みの事実）

| 区分 | 場所 | 内容 |
|---|---|---|
| 起動 | `index.html` → `js/main.js` | 通常の `<script>` を72本、順番に読み込む（ビルド不要）。`MochiQuest.boot()` で起動 |
| エンジン | `js/core/engine.js` | ゲームループ（requestAnimationFrame）、入力（`Engine.Input`：keys / pressed / consume）、シーンの積み重ね（`Engine.push/pop/replace/top`）。キャンバス 640×416（20×13タイル、1タイル32px） |
| マップ | `js/core/map.js` | `GameMap`：タイル配列、建物（足元を `bld_block`、扉を `bld_door` にしてワープを自動生成）、NPC、宝箱、イベント、通行判定 `passable()` |
| 探索 | `js/rpg/world.js` | `World`：マップ切替 `enterMap`、探索シーン（移動・NPC の徘徊・描画）、`onStep`（ワープ・イベント・エンカウント・歩数）、`interact`（話す・調べる）、`talk`、`openChest`、HUD |
| 状態・セーブ | `js/rpg/state.js` | `State.data`（主人公・仲間・所持品・フラグ・位置・時刻 `timeOfDay`・設定）。LocalStorage キー `mtq-rpg-v2-slot-0..3`（0=オートセーブ）。`?debug=1` のときは `mtq-rpg-v2-debug-slot-*` |
| 画面部品 | `js/ui/windows.js` ほか | メッセージ・選択肢・リストは **DOM**（`#ui` の上）で、`ModalScene`（overlay シーン）として積まれる |
| 戦闘 | `js/rpg/combat.js`、`js/ui/battle.js` | 戦闘はキャンバスに描く通常シーン（overlay ではない） |
| トレード学習 | `js/ui/trade.js`、`js/ui/services.js` | 修行場の師匠 → `Services.dojo()` → DOM のパネル（チャートは `<canvas>`、「学習用の人工チャート」表示あり） |
| データ | `js/data/*.js` | マップ226枚（フィールド12・町21・屋内109・ダンジョン84）、敵191種（`ENEMIES` のキー数）、アイテム189、職業20、特技107、乗り物3、仲間14 |
| 画像 | `assets/` | 立ち絵・モンスター画像など（`js/core/assets.js` が `index.html` と同じ階層を基準に読む） |

### 1-2. 3D化で重要だった性質

1. **ゲームの中身と描画が分離しやすい**：移動の結果は `World.player.x / y / dir`、NPC は `GameMap.npcs[i].x / y / nx / ny / prog / dir / hidden` という「データ」で持っている。描画は `ExploreScene.draw` と `GameMap.draw` に集まっている。
2. **会話・メニュー・ショップ・トレード学習は DOM**：3D の画面の上に重ねればそのまま使える。
3. **シーンの積み重ね**：メッセージは overlay（下の探索シーンも描画される）、戦闘は非 overlay（戦闘だけ描画）。この性質を使えば「探索中は3D、戦闘は2D」の切り替えを自然に判定できる。
4. **ポヨ村は 48×40 タイル**（`towns.js` の `ENLARGE` で2倍化済み）、建物6棟（村長の家・道具屋・宿屋・教会・トレード修行場・農夫の家）、屋内6か所（いずれも 12×9）。

## 2. 方針（Phase 1 で実装済み）

### 2-1. 2D版を壊さない

- 2D版の `index.html`・`js/`・`assets/`・セーブデータは **上書きしない**。
- 3D版は **`/3d/`** に置く（ビルド済みの静的ファイル。npm 不要で GitHub Pages でそのまま動く）。開発用ソースは **`three-src/`**。
- 2D版への変更は `js/rpg/state.js` の **数行だけ**（後述のセーブ分離）。2D版の挙動は変わらない（2D版では `MTQ_SAVE_PREFIX` が未定義なので従来どおり）。

### 2-2. ゲームの中身は1か所（js/）だけ

- `/3d/index.html` は2D版と **同じ** `../js/*.js` を読み込む。物語・クエスト・会話・ステータス・戦闘・アイテム・乗り物・トレード学習・セーブの処理は2D版のコードがそのまま動く。
- ビルド時に、2D版 `index.html` から「画面の部品（`#app`）」「スクリプトの一覧」「スタイル」を自動で取り出して3D版に差し込む（`three-src/vite.config.js` の `mtq-legacy-2d`）。2D版にスクリプトを足せば、再ビルドで3D版にも入る。

### 2-3. ハイブリッド表示（段階的移行）

| 状況 | 表示 |
|---|---|
| 3D化したマップ（`MAPS_3D`：ポヨ村＋屋内6か所）を探索中 | **3D**（`#game3d` を `#game` の上に重ねる） |
| メッセージ・選択肢・メニュー・ショップ・トレード学習（DOM） | 3D の上にそのまま重なる |
| 戦闘・タイトル・3D未対応のマップ（ワールドマップ・他の町・ダンジョン） | 従来の **2D** キャンバス |
| 3D の準備中・WebGL が使えない・読み込み失敗 | 2D（または準備中の表示）。2D版として最後まで遊べる |

判定は毎フレーム：「いちばん下に描かれるシーン（overlay を除く）が探索シーン」かつ「今のマップが `MAPS_3D` に含まれる」なら3D。

### 2-4. 探索シーンの差し替え（GameBridge）

`World.start` をフックし、生成された探索シーンの3つのメソッドを包む。

| メソッド | 3Dマップにいるとき | それ以外 |
|---|---|---|
| `handleInput` | 決定＝3D版の「話す・調べる」、キャンセル＝既存メニュー | 2D版のまま |
| `update` | 2D版の update（NPC の徘徊・ミニマップ）を実行したあと、3D の自由移動 | 2D版のまま |
| `draw` | 何もしない（2D の地図を描かない） | 2D版のまま |

**移動**：WASD／矢印キー（押しっぱなし＝走る、Shift＝歩く）、スマホは画面左側のスティック（倒し具合で歩き／走り）。主人公は半径0.28の円としてタイル（`Tiles.isSolid`・固定イベント）と NPC から押し出す。
**タイルをまたいだら** `World.player.x / y / dir` を更新して `World.onStep()` を呼ぶ → 出入口・ワープ・イベント・歩数・ミニマップは2D版の処理がそのまま働く。
**話す・調べる**：主人公の正面（扇形）で最も近い NPC／宝箱／イベントを選び、`World.talk()`・`World.openChest()`・`Events.run()` を呼ぶ（カウンター越しの店主も対応）。対象がなければ向きを4方向に丸めて `World.interact()`（看板・本棚など）。
**NPC**：2D版の徘徊データ（`n.x→n.nx` を `n.prog` で補間）をそのまま3Dの位置にする。話している間と、近くに主人公がいるときは主人公の方を向く。

### 2-5. 座標の対応

- タイル x → ワールド **X**、タイル y → ワールド **Z**、高さ → **Y**。1タイル＝1.0。
- タイル (x, y) の中心は (x+0.5, h, y+0.5)。2D の「上」＝ −Z（北）。カメラは北を画面の上に固定（ミニマップ・2D版と上下左右が一致）。
- 方向：down=+Z（yaw 0）、up=−Z（yaw π）、left=−X、right=+X。

### 2-6. セーブの分離

- `/3d/index.html` は `state.js` より前に `window.MTQ_SAVE_PREFIX = 'mtq-3d-slot-'` を設定。`state.js` はこの値が `mtq-3d-…slot-` の形のときだけ保存先として使う。
- 3D版のセーブ：`mtq-3d-slot-0..3`（`?debug=1` では `mtq-3d-debug-slot-*`）。**2D版のキー（`mtq-rpg-v2-slot-*`）には書き込まない。**
- タイトルの「2D版のセーブを取り込む」：2D版のセーブを `State.loadNormal()` で読み取り専用で読み、3D版の枠へコピー。元の2D版セーブはそのまま。
- 3D版だけの設定（画質・カメラ角度）は `mtq3d-quality`・`mtq3d-pitch`。

## 3. 3D 技術構成

| 項目 | 採用 | 備考 |
|---|---|---|
| 描画 | Three.js 0.186.1（WebGL2） | ES Modules。Vite でビルドし `/3d/assets/*.js` に出力 |
| ビルド | Vite 8.3.4 | `three-src/` で `npm run build` → `/3d/` |
| モデル形式 | GLB（glTF 2.0） | Blender 5.2（Python／bpy）でスクリプト生成：`three-src/tools/blender/build_assets.py` |
| テクスチャ | JPG 512〜1024px（周期的） | `three-src/tools/textures/make_textures.py`（ノイズ・ボロノイから生成） |
| 確認 | Playwright（Chromium） | 画面写真・操作・セーブ分離・2D回帰 |

### 3-1. モジュール

```
three-src/src/
  main.js                     入口（フック → 2D起動 → 3D素材の読み込み）
  bridge/GameBridge.js        App3D：2Dゲームとの接続、表示切替、移動、話す・調べる、描画ループ
  engine/Renderer3D.js        レンダラー、ブルーム（高画質のみ）、画質、サイズ追従
  engine/LightingManager.js   太陽・空・霧・昼夜・窓明かり・ランタンの点光源（近い順に使い回す）
  engine/CameraController3D.js 見下ろしカメラ（角度・ズーム・追従）
  engine/ModelManager.js      GLB の読み込み・複製・インスタンス化
  engine/Flatten.js           色を頂点カラーへ移して部品をまとめる（描画回数の削減）、キャラの SkinnedMesh 結合
  engine/Materials.js         テクスチャ・共通マテリアル・形状の結合（Batch）・看板の文字
  world/MapScene3D.js         GameMap 1枚 → 3D の場面（当たり判定・NPC・宝箱・煙）
  world/TerrainBuilder3D.js   地面（高さ・塗り分け）、道、草、木（BatchedMesh＋LOD）、小物、村の門
  world/BuildingBuilder3D.js  建物（土台・しっくい・木組み・窓・扉・屋根・煙突・看板・鐘楼・幟）
  world/InteriorBuilder3D.js  屋内（床・壁・窓・家具・施設ごとの飾り・灯り）
  entities/Character3D.js     スキンつきキャラクター＋アニメーション9種、足元の影、隠れたときのシルエット
  ui/UIOverlay.js             読み込み表示・「話す」案内・3D設定・スマホのスティック
  assets/manifest.js          モデル管理表（modelId・パス・拡大率・向き・足元・アニメ・LOD・代替・状態）
  viewer.js                   モデル・アニメーション確認ページ（/3d/viewer.html）
```

### 3-2. 描画の工夫（性能）

| 手法 | 内容 |
|---|---|
| 結合（Batch） | 建物はすべて「材質ごとに1つ」に結合（村全体で約20回の描画） |
| 頂点カラー化（Flatten） | Blender のモデルは部品ごとに色が分かれている（例：本棚25色）→「つや消し／金属／発光」の最大3つへ |
| インスタンス化 | 樽・街灯・柵・花壇など同じ小物は InstancedMesh |
| BatchedMesh＋LOD | 木は全種類（針葉樹3・広葉樹3）を1つの BatchedMesh に入れ、主人公から一定距離より遠い木は低ポリゴン版（LOD1）に差し替える。木ごとに画面外を省く（影の描画も同様） |
| チャンク | 草は 16×16 タイルごとの InstancedMesh（画面外の区画を省く） |
| 地形 | 1枚の格子。村の中は 0.5 間隔、遠くほど粗く（遠景の山まで1回の描画） |
| 灯り | 点光源は高画質8個・軽量4個を「主人公に近いランタン」へ毎フレーム割り当て |
| 画質 | 高（PC）：影2048・ブルーム・MSAA・草多め／軽量（スマホ）：影1024・ブルームなし・解像度控えめ・草と木を減らす |
| 段階的読み込み | ポヨ村の素材だけを読み込む（全地域を一度に読まない）。屋内は村の完成後に裏で組み立ててキャッシュ |

## 4. カメラ角度の比較（35〜55°の範囲）

3D設定で 38°／48°／56° を切り替えられる（既定 48°）。比較用の画面写真は `docs/3d/images/` にあります。

| 角度 | 長所 | 短所 | 判断 |
|---|---|---|---|
| 38°（低め） | 奥行きと空気感が出る。建物の正面がよく見える。遠くの丘・山が画面上部に入る | 建物の裏側に入ると主人公が隠れやすい（→シルエット表示で補う）。奥が見えにくい | 景色を見せたい場面向き |
| **48°（既定）** | 建物の正面と屋根の両方が見え、2D版の見下ろし感に近い。操作方向と画面の対応がわかりやすい | 空は見えない | **探索の既定値** |
| 56°（高め） | 迷いにくい。広く見渡せる。屋内向き | 立体感が弱くなる | 屋内は 55° を使用 |

## 5. 未決定・リスク・確認が必要な点

- **性能の実測**：この開発環境には GPU がなく、Chromium のソフトウェア描画（SwiftShader）でしか確認できていない。描画回数・三角形数は計測済みだが、**実機（PC・スマホ）の fps は未確認**。
- **戦闘の3D化**：Phase 1 では戦闘は2D表示のまま（`battle.js` を使用）。
- **職業ごとの主人公モデル**：Phase 1 は主人公モデル1種（剣と盾の勇者）。2D版の職業（戦士・魔法使いなど）に応じた見た目の切り替えは未実装。
- **2D版の `debug.js`（`?debug=1`）の「通常のセーブを読み込む」** は3D版では「2D版の通常セーブ（読み取り専用）」を読む動きになる。
- 3D化したマップの数が増えると、ビルド済みのファイルが大きくなる（モデルは地域ごとに分けて読み込む設計を継続する）。
