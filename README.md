# もちぽよFXクエスト ～波形の勇者と相場の魔王～（JRPG版 v4.0）

2DトップビューのJRPGとして、アルカディア相場大陸を歩き、町で買い物をし、仲間を集め、ダンジョンに挑み、ターン制バトルで戦いながら、FXトレードの判断（上位足・ダウ理論・EMA・RCI・MACD・資金管理）を「チャートの試練」で学べるブラウザゲームです。

- 公開URL: https://mochipoyo.github.io/mochipoyo-trade-quest/
- HTML / CSS / Vanilla JavaScript / Canvas 2D のみ。ビルド・サーバー・外部CDN・外部API・画像ファイル不要（ドット絵はすべてコードで生成）
- ゲーム内のチャートは **学習用の人工データ** です。実際の市場データではありません
- セーブはブラウザの LocalStorage（3スロット＋オートセーブ）。JSONの書き出し／読み込みも可能

### 実装したもの
1. **ポヨ村のチュートリアル「はじめてのトレード」**（師匠ハケイ）: ①ローソク足の基本（陽線・陰線の図付き）→②買いと売り・損切り→③上昇・下降・レンジ→チャート表示→分析→買い/売り/見送り→理由の選択→正解と解説→**初回学習報酬（100G・薬草×2・経験値15、1回だけ）**。「説明を短縮して挑戦」で経験者は短縮可。修行場のハケイに初めて話しかけると自動で始まり、修行場メニューとメインメニューから何度でも復習できる（復習では報酬なし）
2. **メインメニュー「トレード修行」**（旧「トレード記録」を置き換え）: 今の学習テーマ／チュートリアル／講義（どこからでも受講可）／チャート練習／苦手分野の復習／トレーダーランク／学習進捗・記録。重要な学習イベント完了時に次のおすすめを案内
3. **正解の事前表示を削除**: 練習一覧の「正解：買い…」を撤去（「正解は回答後に表示」）。「インジケーター確認」で分析結果を教える方式を廃止し、**段階式ヒント**（①考え方 → ②場面のヒント → ③数値表示）に変更。ヒント使用は記録に残る
4. **自分で分析してから判断する流れ**（`js/ui/trade.js` 書き直し）: ①上位足（4時間足）の方向 ②15分足の波形（ダウ理論） ③EMA20/30/40の並び ④RCI(9)の状態 ⑤MACD(6,13,4)のダイバージェンス の5問に答えてから、買い/売り/見送り → **理由を6択から選ぶ**（誤った理由「RCIが±70なので逆張り」「勢いがあるので乗る」も混在）→ トレードなら損切り・利確・リスク%を設定。5問に答えるまで判断ボタンは機能しない。未来の足は判断後にのみ表示
5. **採点と解説の改善**（`TradeEval.evaluateFull`）: 判断過程に重点。分析40点（10/8/7/7/8）＋行動30点＋理由10点＋損切り10・リスクリワード6・資金管理4（見送り時は見送り判断20）＝100点。採点の「真の状態」（`TradeEval.truth`）は**表示チャートと同じ計算結果**から取り、結果画面に項目ごとの ✓/✗・あなたの答え→実際・配点を表示。解説文は実際の状態から組み立て、確認不足の項目を指摘。利益が出たかどうかは点数に影響しない（表示のみ）。行動が誤りなら理由点は0、方向違いのトレードは注文管理点を半減
6. **分野別の学習記録**（`State.data.trade.topics`）: 9分野（上位足・ダウ・EMA・RCI・MACD・判断・理由・損切り/資金管理・見送り）× 挑戦数・正解率・ヒント利用率・習熟度（未習熟/練習中/理解/苦手）・前回の結果。「苦手分野の復習」は正解率の低い分野に合う場面を出題
7. **トレーダーランク F〜S**（`TradeEval.rank`）: 分析の正確さ・上位足認識・判断・損切り/見送り・**ヒントなし正解率**・**異なる場面での正解数**・平均点を総合。同じ場面の繰り返しでは上がらない（自動テスト：同一場面30回正解でもE止まり、全14場面を正確に分析するとS）
8. 既存14シナリオに「判断の理由」の正解を付与。学習スコア・報酬は1回の試練につき1回だけ確定（二重採点ガード）

## v3.2 ミニマップ・ワールドマップ 報告

> 作業ブランチ: `feature/graphics-v3`。既存の座標データ（`GameMap.tiles / buildings / warps / chests / events`、`WORLD_LOCATIONS`）をそのまま使い、手作業の地図は持ちません。

### 実装内容
- **右上ミニマップ**（`js/ui/minimap.js` 新規、`#minimap-layer`）: ゲームCanvasの表示領域を基準に右上へ配置（PC 160×120px / スマホ 104×78px、設定で1.3倍）。マップ名・コンパス（N）・金色の矢印（向きに回転・発光）・地形の色分け・施設アイコン・階段/出入口/宝箱/扉の記号。プレイヤーを中心に追従し（移動中は補間）、端では表示範囲を補正。既存HUD（場所・ゴールド・HP/MP）は**左側に縦並びへ再配置**して重ならないようにした
- **拡大マップ**: ミニマップのクリック/タップ、**Mキー**で開閉。閉じる（✕・Esc・M）。開いている間は主人公は移動しない（`World.busy`）。ズーム（ホイール・ピンチ・＋/－）、ドラッグ/スワイプで移動、「◎ 現在地」、凡例、上部にマップ名
  - **現在のエリア**: 町では施設アイコン（12タイプの統一デザイン）を**実際の建物の入口座標**に表示し、タップで施設名（例「ポヨ村の宿屋」）。ダンジョンでは通路・壁・階段・出入口・宝箱（開封済みは表示変更）・鍵の扉/試練の扉/強敵の印
  - **世界地図**: 160×120のワールド全体（海・山脈・森・砂漠・雪原）、**訪問済み**の町・**発見済み**のダンジョンを名前付きで表示。現在地は、ワールド上ならその座標、町・ダンジョン・建物内部なら `WORLD_LOCATIONS` と各マップの接続（ワープ・建物の内部）を親マップへたどって解決（例: ポヨ村の宿屋 → ポヨ村 → (28,58)）。解決できないマップにはマーカーを出さず「現在地：不明」と表示
  - **階層**: ワープでつながるダンジョン群（忘却の洞窟 1階/2階/最深部）をタブで切替。未訪問の階は「？？？」で選べない
- **Fog of War（ダンジョンのみ）**: 歩行完了・マップ進入時に、通行可能なタイルを半径3まで幅優先でたどり、その隣接する壁まで「発見」。壁越しの部屋は見えない。未探索は暗く塗りつぶし、未発見の宝箱・隠しボスの印は表示しない
- **保存**: `State.data.mapDiscovery[マップID]` に行ごとの30bit整数の配列で保存（洞窟3階分で約160文字）。`visited` は変更なし。旧セーブは `State.migrate` のテンプレート合成で `mapDiscovery:{}`・設定の既定値が補われる（実機で確認済み）
- **設定**: 「ミニマップ：表示する/表示しない」「ミニマップの大きさ：ふつう/大きい」を追加（セーブに保存）
- **非表示になる場面**: タイトル・戦闘・リザルト・チャート画面・会話や各種ウィンドウ表示中・メニュー中・拡大マップ表示中（探索画面に戻ると再表示）
- **描画**: 地形はマップごとに専用の簡略タイル（1タイル=2〜10px）で1回だけ描いてキャッシュ。移動では再生成しない。宝箱/扉の状態変化（`World.applyState`）と探索範囲の更新時だけ再生成。拡大マップはDPR対応でぼやけない
- **キー**: `m/M` を `Engine.Input` に追加（探索シーンでのみ反応。入力欄・設定・戦闘では無効）

## 3. 公開後の動作確認

1. タイトル → 「はじめから」→ 名前入力 → 職業選択（8種から）→ ポヨ村で目覚める
2. 矢印キーで歩ける。木や壁は通れない。村長の家（北西の赤い屋根）に入り村長と話す → 100G・薬草・木の剣をもらう
3. 教会でリーナを仲間にする。道具屋で薬草を買う。宿屋で休む
4. 村の南の出口からフィールドへ。歩くとランダムエンカウント。「たたかう／じゅもん・とくぎ／どうぐ／ぼうぎょ／にげる」で戦う
5. 北の道でリヴェル城下町へ。城で王に謁見 → クエスト。酒場でカイル加入。武器屋・防具屋で装備を買う。ギルドで転職。銀行で預金
6. 東の森「迷いの森」へ。試練の扉でチャート分析（60点以上で開く）→ 祠でボス「トレンド迷子」→ 鍵の扉 → 伝説の「波形の剣」
7. 王に報告 → 洞窟の鍵 → 南東の「忘却の洞窟」（3階・落とし穴・封印扉・試練の扉）→ ボス「欲望のゴーレム」→ クリスタルの欠片
8. 修行場（ポヨ村・ダウの村）で講義・チャートの試練・学習クエスト。ダウの村でミナ、港町でガルド、講義修了後にルシアが仲間になる
9. メニュー → セーブ。再読み込み → 「つづきから」で再開できる

## 7. 追加・調整のしかた
- 町：`js/data/towns.js` の `buildings:[{ type, name, x, y, w, h, doorX, interior, entry }]`。`type` は weapon/armor/item/inn/church/tavern/bank/guild/dojo/house/elder/warehouse/castle/ship。扉と室内への移動は自動生成
- ダンジョン：`js/data/dungeons.js` に `add({...})`（ASCIIマップ＋warps/chests/events/encounters）。装飾は `decorate(rows)` を通すだけ
- モンスター：`js/data/enemies.js` の `M(id, { name, lv, arche, art:{ family, ...特徴 }, family, area, actions, drops, resist, desc })`。`lv` と `arche`（normal/tank/fast/mage/glass/rare）からステータスを自動生成。出現させるには `world.js` / `dungeons.js` の `groups` に追加
- モンスターの見た目：`art.family`（slime/beast/bird/insect/plant/aquatic/reptile/undead/demon/golem/spirit/magical/machine/market）＋特徴フラグ（horns/tusks/teeth/stripes/wings/striped/stinger/mandibles/shell/petals/mushroom/crown/crab/octopus/snake/frill/dragon/ghost/zombie/weapon/trident/gem/rune/antenna/core/spikes/metal/drip/big/angry/crest/mimic/candle/bear/bull）＋`size`（small/normal/big/boss）＋`c.base` などの色
- 敵の行動：`actions` の `{ type:'special', id, w, hpBelow }`。`hpBelow: 0.4` でHP40%以下のときだけ選ばれる。`id:'call', summon:'slime'` で召喚
- 戦闘背景：`js/ui/battle.js` の `themeFor()`（地域名/マップIDからテーマを決定）と `BattleBG.render()`
- 職業・特技・アイテム：`js/data/jobs.js` `skills.js` `items.js` にデータ追加のみ
- 学習シナリオ：`js/scenarios.js` の `SCENARIO_DEFS`。試練の扉・魔物の `trialScenarios` で参照
- 戦闘計算式：`js/rpg/combat.js` の `physDamage` / `magDamage`
